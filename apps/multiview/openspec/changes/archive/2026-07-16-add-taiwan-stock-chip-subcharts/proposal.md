## Why

目前多圖面板只能從價格、成交量與技術指標判讀台股，缺少能與日 K 對齊的個股籌碼資料。加入可追溯來源的三大法人、外資持股、融資融券、借券與集保股權分散副圖，可讓使用者在同一個面板比較價格走勢、每日籌碼變化及每週大戶／散戶持股結構，同時避免把買賣超、外資持股與依持股級距推導的市場稱呼混為一談。

## What Changes

- 為上市 `.TW` 與上櫃 `.TWO` 普通股提供每日與每週個股籌碼資料；ETF、權證、指數、海外商品與盤中即時籌碼不納入本次範圍。
- 新增外資、投信、自營商及三大法人合計每日買賣超資料，內部保存官方股數，普通股顯示時換算為張數；自營商保留自行買賣、避險與合計的可辨識欄位，三大法人合計由完整分項相加並以來源總計交叉驗證。
- 新增外資及陸資持股股數與持股比率；不提供或推算不存在的投信持股比、自營商持股比。
- 新增融資、融券每日買賣／償還／餘額／增減與資券互抵資料，並納入可取得的借券及借券賣出資訊。
- 新增 TDCC 集保戶股權分散週資料，依官方持股分級計算預設「超過 1,000 張」大戶與「10 張以下」散戶的持股比例、股數及人數，並允許使用者選擇可由官方級距精確組成的門檻。
- 本次不納入八大行庫買賣超；券商分點名單、資料授權與歷史來源留待後續獨立 change 評估，不作為本次完成條件。
- 使用允許自動介接的 TWSE／TPEx／TDCC 官方 OpenAPI、政府開放資料及具明確 API 規範的免費歷史來源；不得以未經允許的網頁爬取作正式資料鏈。
- 使用 Sites D1 保存按個股取得、驗證成功的日資料、TDCC 全市場週快照與來源 metadata，支援歷史回補、增量更新、快取、去重及來源失敗時沿用最近成功資料。
- 新增同源個股籌碼 API，依 symbol 與日期範圍回傳正規化資料、實際資料日期、來源、更新時間、完整度與安全 warning。
- 在每個台股日 K 面板的籌碼副圖選單加入外資、投信、自營商、三大法人合計、外資持股、融資、融券、借券、大戶持股與散戶持股；每個顯示項目使用獨立 pane 與適合自身單位的尺度，並與主圖時間軸、十字線及歷史載入保持同步。
- 新增「方式 A／單一副圖」與「方式 B／多層副圖」：方式 A 一次顯示並替換一個籌碼 pane；方式 B 依勾選項目建立或移除多個上下堆疊 pane。A／B 只管理本次新增的籌碼副圖，既有 RSI、KD、MACD、ATR 技術副圖維持原行為。
- 圖表數量新增 3 圖；1、2、3 圖可切換 A／B 且首次預設 B，4、6、8 圖固定 A。跨圖數切換 MUST 保留使用者在 B 的勾選組合與 A 的最後作用項目，返回 1、2、3 圖時恢復先前偏好。
- 方式 B 首次使用預設顯示三大法人合計、融資、融券、大戶持股與散戶持股；之後沿用裝置端保存的使用者選擇。多 pane 採固定順序、最小可讀高度與 panel 內垂直捲動，不以無限壓縮高度容納所有勾選項目。
- 對非台股普通股、非日 K、資料尚未發布、來源暫時失敗或部分欄位缺漏提供中性且可診斷的狀態，不以零值偽裝缺少資料。
- 加入資料解析、來源切換、D1 migration、API、圖表、時間對齊、快取、容錯與正式 Codex Site 可見行為驗收。

## Capabilities

### New Capabilities

- `taiwan-stock-chip-data`: 定義上市／上櫃個股籌碼資料的來源、欄位語意、正規化、日／週頻時間對齊、D1 持久化、API、來源診斷與安全要求。
- `taiwan-stock-chip-subcharts`: 定義個股籌碼副圖的適用範圍、A／B 顯示模式、1／2／3／4／6／8 圖規則、pane 選擇與保存、單位、尺度、法人／信用資料讀值、每週大戶／散戶柱狀圖、時間同步、缺資料狀態與多圖互動。

### Modified Capabilities

- `codex-sites-rewrite`: 擴充 Workers 市場資料與多圖 parity，讓 Sites runtime 能按需提供、快取並呈現台股個股籌碼資料，且納入正式部署驗收。

## Impact

- 前端：`public/static/index.html`、`public/static/app.js`、`public/static/styles.css` 的 3 圖版面、A／B 控制、裝置端偏好、pane manager、副圖選單、圖表建立／銷毀、讀值、時間同步、捲動、載入與錯誤狀態。
- Worker：新增個股籌碼 route、來源 adapter、正規化與快取服務，並與既有 `/api/candles` 歷史範圍及 panel lifecycle 協調。
- 資料庫：擴充 `db/schema.ts`、Sites D1 migration、runtime schema 初始化與測試用 FakeD1。
- 外部系統：TWSE／TPEx／TDCC 官方資料、政府開放資料及可選的免費歷史 API；任何 token 只能存放在 Sites runtime 環境變數，repo、OpenSpec、前端與診斷輸出不得出現秘密值。
- 驗證：`npm test`、OpenSpec strict validation、本機 API／UI smoke，以及已登入的 Codex Sites 正式站上市與上櫃代表個股驗收；UI 驗收涵蓋 1／2／3 圖 A／B、4／6／8 圖強制 A、跨圖數狀態恢復與多 pane 最壞負載。
