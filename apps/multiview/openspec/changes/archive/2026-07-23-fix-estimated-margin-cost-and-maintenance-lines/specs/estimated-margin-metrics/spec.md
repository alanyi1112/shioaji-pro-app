## MODIFIED Requirements

### Requirement: 估算融資成本的逐日計算

系統 MUST 以同一商品逐日融資餘額、融資買進張數與日 K 收盤價，使用移動平均成本法計算「估算融資成本」；新增融資部位 MUST 以當日收盤價加入成本，融資賣出與現金償還 MUST 以原平均成本減少部位而不重估剩餘成本。第一筆可計算日期 MUST 以該日收盤價建立種子並標示 `seeded`；流量或跨交易日餘額無法核對時 MUST 保留 gap，後續第一個本身流量及跨列餘額皆可核對的交易日 MUST 以當日收盤價建立新區段並標示 `reseeded`。結果 MUST 附帶 `formulaVersion`、資料日期及估算註記，不得稱為投資人實際融資買進均價。

#### Scenario: 融資餘額增加
- **WHEN** 前一日有合法估算成本與融資餘額，且當日融資買進後仍有未償餘額
- **THEN** 系統 MUST 以「前一日未償部位成本加上當日融資買進張數乘當日收盤價」除以買進後部位計算新平均成本
- **AND** 當日融資賣出與現金償還 MUST 以該平均成本扣除，不得改變剩餘部位的每股估算成本

#### Scenario: 第一筆或歸零後重新建立部位
- **WHEN** 查詢範圍第一筆合法資料已有融資餘額，或前一日融資餘額為零而當日重新出現餘額
- **THEN** 系統 MUST 以當日收盤價作為該段部位的估算成本種子
- **AND** response MUST 將該點標示為 `seeded`，UI MUST 可揭露其不是完整歷史成本

#### Scenario: 流量與餘額無法核對
- **WHEN** 融資買進、賣出、現金償還與前後餘額的單位不一致、缺漏或超出允許的來源調整差異
- **THEN** 系統 MUST 將該日估算成本標示為 `null` 或 `partial`
- **AND** MUST NOT 以零值、未揭露的固定價格或任意回推結果接續成本序列

#### Scenario: 中斷後恢復合法流量
- **WHEN** 前一筆因 `balance_mismatch` 或輸入缺漏中斷成本鏈，且後續某交易日的前日餘額與上一列今日餘額一致、當日流量亦可核對
- **THEN** 系統 MUST 在中斷日保留 gap，並以該後續交易日收盤價建立新的估算成本區段
- **AND** response MUST 標示 `status=reseeded`、`reseeded=true` 與新版 `formulaVersion`
- **AND** MUST NOT 將中斷前平均成本沿用到未知調整後的部位

### Requirement: 估算融資維持率的逐日計算

系統 MUST 只在同日具有合法收盤價與估算融資成本時，依個股估算公式 `收盤價 ÷（估算融資成本 × 60%）× 100%` 計算「估算融資維持率」。固定 60% MUST 在 response 與 UI 詳細資料中標示為估算模型參數，不得宣稱為商品當日實際融資成數、個別券商授信成數或客戶帳戶實際維持率。

#### Scenario: 所有輸入皆合法
- **WHEN** 某交易日具有合法收盤價與估算融資成本
- **THEN** API MUST 使用固定 60% 模型參數，回傳該日估算融資維持率、融資餘額變化張數、輸入值、模型來源與 `formulaVersion`
- **AND** UI MUST 以百分比顯示維持率並保留「估算」名稱

#### Scenario: 揭露固定 60% 模型參數
- **WHEN** API 回傳估算融資維持率
- **THEN** response MUST 同時回傳 `marginLoanRatio.percent=60` 與可辨識的估算模型來源
- **AND** UI 詳細資料 MUST 說明該值不是商品實際融資成數

#### Scenario: 估算成本或收盤價缺漏
- **WHEN** 某日缺少估算融資成本或合法收盤價
- **THEN** 該日估算融資維持率 MUST 為 `null` 並提供可辨識原因
- **AND** MUST NOT 沿用前值或內插

#### Scenario: 舊版副圖偏好已啟用融資券群組
- **WHEN** 使用者的舊版非空副圖偏好已選取至少一個融資券 pane，但尚未包含「估算融資維持率」
- **THEN** 系統 MUST 一次性補入「估算融資維持率」pane，並保留其他既有選取與排序
- **AND** 偏好升級後若使用者明確移除該 pane，系統 MUST NOT 再自動加回
