## Context

每個圖表 panel 先以 `/api/candles` 套用完整 payload，再連線 `/api/stream`。stream 約每 20 秒推送最新 candle；即使台股已收盤且價格沒有改變，現行 `updateLatestPriceState` 仍無條件觸發 850ms 的漲跌底色動畫。這個動畫原本用來提示即時價格更新，但目前實際只代表「收到 payload」，無法可靠代表「價格變動」。

## Goals / Non-Goals

**Goals:**

- 將動畫觸發條件改成「同一 panel 已呈現過價格、最新價格真的改變、且市場仍在交易」。
- 讓 `/api/candles` 初次載入、相同 candle 重送、台股收盤 candle 都維持穩定底色。
- 不影響價格方向、漲跌幅、漲跌停樣式與收盤核對文案。

**Non-Goals:**

- 不變更 `/api/stream` 的 20 秒傳送週期或跨市場串流架構。
- 不調整收盤價官方核對、freshness 判定或報價 API schema。
- 不重新設計整個商品報價列的視覺樣式。

## Decisions

1. 每個 panel 保存最後一次已呈現的有限價格，並在更新畫面前比較新舊值。初次載入沒有可比較基準，因此不顯示「更新」動畫；相同價格重送也不顯示動畫。相較於用 candle 時間判斷，直接比較價格更符合動畫要傳達的意義，也不會被上游重送相同資料誤觸發。
2. 動畫判斷同時要求 `marketSessionState(payload) === "open"`，並排除 `quote.kind === "session-close"`。使用既有正規化市場狀態，避免在前端另做一套台股時鐘判斷；雙重條件可防止不一致 payload 將已完成收盤誤當盤中。
3. 價格文字、方向與核對狀態仍在每次 payload 更新時重新渲染，只有瞬間底色動畫受到抑制。因此官方資料由待核對轉為已核對時，狀態文字仍會正常更新。
4. 新增可獨立測試的純判斷函式，覆蓋初次價格、相同價格、盤中變價、收盤變價與 `session-close` 防護。

## Risks / Trade-offs

- [市場狀態 payload 暫時缺失] → 沿用既有 `marketSessionState` fallback；只有判定為 open 才允許動畫，採保守策略避免假訊號。
- [盤後真有價格更正但沒有動畫] → 價格與核對文字仍會更新；這次刻意不把一般即時漲跌動畫用於盤後更正，後續若需要可另設明確的「收盤價已更正」提示。
- [浮點表示造成極小差異] → 目前畫面與資料皆使用同一數值來源，採有限數值嚴格比較；若資料來源未來產生精度雜訊，再依商品 tick size 正規化。
