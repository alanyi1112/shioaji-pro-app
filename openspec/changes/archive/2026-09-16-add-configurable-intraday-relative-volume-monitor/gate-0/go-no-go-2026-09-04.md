# Gate 0 go／no-go 報告

## 結論

**NO-GO：只允許保存 configured 名單與執行離線 domain／fixture 測試；不得建立盤中監控 subscription。**

```text
gate0EvidenceCurrent=false
globalOwnershipComplete=false
subscriptionTransportAuthority=false
subscriptionCountingDimension=unknown
unsubscribeConfirmation=unknown
baselineBootstrapQualified=false
activeCapacity=0
```

這是安全完成的 Gate 0 判定，不是功能失敗。設定層仍可支援最多 200 檔；UI 與 API 必須把它們顯示為 `waiting_gate`，不得聲稱 active。

## NO-GO 下允許與禁止的工作

允許：

- 純 TypeScript domain、runtime schema 與 deterministic fixtures。
- config draft／repository 的 feature-off 實作，只要 GET 不產生 provider side effect。
- UI 顯示 configured、waiting_gate、blocker 與 active=0。
- 離線 replay、migration 與資料完整度測試。

禁止：

- 為盤中監控新增任何 quote subscription。
- 以 Snapshot、ticks 或 Kbars 輪詢模擬即時監控。
- 把 200 configured 寫成 200 active。
- 在 current usage／unsubscribe 未確認時套用 160 headroom 公式。
- 啟動 production、第二個 login 或真實下單。服務重啟只能依使用者明確授權，且不得由產品功能自行觸發。
