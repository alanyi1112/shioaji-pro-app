# P0 Requirement／Scenario／Task／Gate 可追溯基線

- Baseline ID：`smart-order-p0-traceability/2026-08-12.1`
- 用途：完成 task 0.18 的可機械審查骨架；逐項指定規範、正常／失敗／競態 Scenario、實作與故障 task、解鎖 Gate、證據責任與目前處置。
- 非用途：本文件不是 Gate manifest、simulation broker write 授權、正式環境授權或 feature release 證據。`部分完成`只表示已有 fail-closed 實作，不表示可送單。

## 狀態與共同規則

1. `已具文件／純 domain 證據`：只能證明該層的 deterministic contract；若 production adapter、Runtime transaction 或真實 capability 尚缺，下一層仍維持 disabled。
2. `部分完成・fail closed`：已有控制，但證據責任尚未全部履行；不得由 UI、環境變數、fixture 或人工勾選升級。
3. `等待 Gate 0／目標環境證據`：必須由受管 runner、固定帳號 read-only／逐次授權 simulation probe、Node LTS `>=24.15.0 <25`原生Apple Silicon `arm64`實機或官方contract產生；mock／fixture、Intel／`x64`、Rosetta、VM、舊雙架構schema或重放report不得替代。未來Intel交易Runtime另立OpenSpec change。
4. 任一列缺少 Requirement、正常 Scenario、失敗／競態 Scenario、task、Gate 或證據責任，整個 artifact 不得標示 `apply-ready`。
5. 任一列證據過期、hash／build／schema／adapter／Shioaji fingerprint 漂移，該列立即退回 disabled；不因其他列通過而繼承資格。

## Apply-ready 與 write-unlock 判定

- 本基線完整後，只能表示 proposal 的 P0 需求已有可追溯責任鏈，符合「可繼續 apply 與執行 Gate 0」的文件條件。
- `P0-02`至`P0-21`中凡標示尚缺 production／Gate／目標環境證據者，仍阻擋 `write-unlock-ready`。
- 目前 Runtime production construction固定使用 disabled broker adapter、readiness回傳false、write master為disabled；不得以本表、測試數量或已勾task推論可送 simulation或正式委託。
