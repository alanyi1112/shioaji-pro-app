## Context

MultiView 籌碼 API 已在 `coverage[]` 逐資料集回傳 `dataset`、實際 `end` 與 `frequency`。目前 UI 只在頁面底部呈現各資料集警示，而群組標題僅有名稱與副圖數量；另外，副圖標題的日期會隨十字線游標位置改變。這三種日期語意沒有清楚分層，造成使用者把外資持股或融資融券的 `2026-09-21` 警示，誤認為 TDCC 大戶／散戶持股也更新到同一天。

本變更只處理顯示語意，不改變資料來源、抓取排程、API schema 或既有日期對齊規則。

## Goals / Non-Goals

**Goals:**

- 在各籌碼群組標題直接顯示目前可見副圖所依賴資料集的實際截止日與日／週頻率。
- 同群組使用多個資料集且截止日不同時，逐一標示，不壓成單一日期。
- 讓資料截止日與十字線游標日期彼此獨立，並在 PNG 匯出中保留群組日期標示。
- 缺少 `coverage.end` 時採取 fail-closed 顯示，不以請求日期、K 線日期或其他資料集日期補值。

**Non-Goals:**

- 不補抓或改寫任何籌碼資料。
- 不統一不同資料集的更新日，也不將週資料偽裝成日資料。
- 不移除既有警示訊息。
- 不變更模式 A 單一副圖配置；模式 A 既有隱藏群組標題的版面維持不變。

## Decisions

### 1. 以 `coverage[]` 作為唯一日期權威

群組日期標示只讀取 API payload 的 `coverage[]`，使用 `dataset` 對應的 `end` 與 `frequency`。不從 `rows` 最大日期、目前 K 線日期、requested end 或警示文字解析日期。

替代方案是沿用警示文字或掃描資料列，但前者是呈現用文案，後者容易把某一資料集的最大日期錯套到另一資料集，因此不採用。

### 2. 依可見副圖推導需要顯示的資料集

日期標示由目前群組內可見副圖的 `dataset`／`datasets` 定義推導，並按照既定資料集順序去重。法人群組可同時顯示買賣超與外資持股；融資券群組可同時顯示融資融券與借券；持股比群組顯示 TDCC 週資料。

這可避免顯示使用者沒有選取之副圖的無關日期，也能正確處理「外資買賣超＋持股」單一副圖同時依賴兩個資料集的情況。

### 3. 使用完整 ISO 日期與明確頻率

標示採 `買賣超（日）至 2026-09-22`、`TDCC（週）至 2026-09-18` 之類的完整格式，避免只有 `09/18` 時產生年份或資料類型歧義。若 `coverage.end` 缺失，顯示 `尚無可驗證日期`。

### 4. 日期標示屬於群組 header，而非圖表 readout

日期節點放在 `.chip-pane-group-header`，與群組名稱及副圖數量同層。它不參與 crosshair readout，因此游標移動不會改變；PNG 匯出既有會擷取整個群組 DOM，因此可自然納入匯出結果。

## Risks / Trade-offs

- [群組標題過長] → 使用可換行／靠右排列與較小字級，窄版時仍保留完整日期，不以省略號隱藏關鍵資訊。
- [舊快取 payload 缺少 coverage] → 顯示 `尚無可驗證日期`，不推測；背景更新取得完整 metadata 後自動刷新。
- [payload 或選取副圖切換後標示殘留] → 在 mode、選取項目、快取載入、網路載入與不可用狀態改變時，統一刷新群組日期節點。
- [模式 A 空間不足] → 延續既有行為隱藏群組 header；本變更聚焦使用者截圖所示的模式 B 多副圖版面。

## Migration Plan

1. 新增純函式，將群組、可見副圖與 `coverage[]` 轉成可測試的日期標示。
2. 擴充群組 controller 建立及刷新日期節點。
3. 加入 CSS 與單元測試，再以本機 2449.TW 實際 payload 驗證各資料集日期。
4. 若需回復，只需移除日期節點、樣式與 helper；API 與資料庫不受影響。
