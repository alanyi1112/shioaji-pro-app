## Context

新系統頁籤清單表已含 00406A.TW，舊資格及背景更新查詢漏讀。既有日籌碼與持股原件保留；選股資料只在通過正式收據與 mapping 驗證後可共用。

## Goals / Non-Goals

目標為身分與更新清單一致、同日期同口徑資料可重用、錯誤精確可診斷。非目標為替來源補零、放寬資格或預算 Gate、改名單、擴大全市場下載、遠端部署。

## Decisions

1. 共用清單查詢涵蓋兩表，前景限制同一 user_id，排程只讀 enabled=1；相同商品去重。
2. 共用資料採 receipt-linked 投影，先驗日期、來源、mapping 與欄位，不覆寫較完整原件；缺少自營商等欄位保持 null。
3. 已完成或已驗證資料優先重用；來源請求維持既有頻率、冷卻與限額，不以更新前端製造驗收證據。
4. 預檢與回歸完成後套用本機；保留部署前摘要與原失敗紀錄。只有原件與可見 UI 同時符合才稱修復完成。

## Risks / Trade-offs

普通股選股母體不應因 ETF 圖表需求而擴大；ETF 只經合法商品資格進入 MultiView 更新。舊報表的欠欄位不得推算成完整三大法人合計。

## Migration Plan

新增共用查詢與讀取投影，避免破壞性 migration。必要原件新增僅沿既有服務契約，保留失敗與來源收據。

23 檔稽核新增 `screener_chip_canonical_rows` 附加表，逐列綁定 verified receipt、mapping、來源觀測時間及內容 SHA。僅保存相同日期／口徑的完整官方欄位；官方修訂用新收據與新版本保留，舊原件不改寫。自然 collector 從同一回應保留完整欄位，不增加資料請求；舊安裝沒有附加表時維持原行為，不在 GET 內 migration。

預熱健康檢查可唯讀使用已驗證共用完整列接續落後的狀態，原 fetch state 不改寫；365 日涵蓋範圍、20 小時 freshness、冷卻與預算 Gate 均保留。診斷分列最新來源、歷史窗口及時效不足，原排程錯誤另列，不將所有 pending 猜成官方未發布。上市前不補資料，借券成交無列不補零；未逐日驗真的稀疏日期保留 unknown。
