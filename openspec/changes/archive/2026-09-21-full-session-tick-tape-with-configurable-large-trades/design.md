## Context

現有 TickTape 用 fetchLastTicks 取 120 筆，以 React state 保存 rows／largeRows；分別截斷為 120／500 筆，seenKeys 只保留 2,000 筆。歷史載入失敗與空資料目前容易混成空列表。大單使用固定 40 萬元、5 張、前 120 筆 P70、30 筆暖機，分類僅適用 09:00:00 < time < 13:25:00。既有 fetchHistoryTicks 可查詢交易日歷史，但回應完整性及即時交接仍須驗證。

## Goals / Non-Goals

**Goals:** 台股成交明細可從任意開啟時間回看當日開盤以來全部成交；大單數值可設定，整組 AND／OR，條件變更後重算完整日，設定與同商品資料可於主面板及獨立視窗一致使用。

**Non-Goals:** 不建立逐筆成交與 1 分 K 相互推造、不擴充 160 檔背景訂閱、不改交易權限。期貨與選擇權既有夜盤交易日處理不得退化，本案新大單設定以台股為範圍，不把台股時段套入期貨。

## Decisions

### 1. 完整日資料與列表顯示分離

以 canonical contract＋交易日隔離資料，採 IndexedDB 分批持久保存成交與 coverage metadata，React 僅保留可見列及必要索引。虛擬列表讓全部／大單任意回捲，不把可見列上限當成資料保存上限。選擇 IndexedDB 是為跨重載保存並避免整日資料塞入 localStorage；若原始來源量測顯示需改用本機 SQLite，須更新設計及測試，不直接無界保留於 React state。

保留當日資料；其他交易日快取依空間策略清理，不能淘汰使用中交易日並繼續聲稱完整。空間不足顯示失敗及已保存範圍，不默默截斷。多人／遠端共用不在本案。

### 2. 歷史補齊與即時銜接

初次載入先建立既有即時事件緩衝，取得開盤至可驗證交接點的歷史，再依來源排序、合併、檢查重疊和缺口。按來源支援使用單次整日查詢或時間範圍分批；全程設 timeout、總 deadline、請求與 bytes 預算，不能以高頻輪詢取代串流。跨面板／視窗由共享協調器或跨頁 lease 合併相同商品交易日請求。

既有「時間＋價格＋張數＋方向」鍵可能誤合併兩筆內容相同但不同的成交，須先檢查來源有無 sequence／ID。沒有唯一鍵時保留批次內重複次數，以可驗證的有序重疊比對銜接；無法確定時顯示缺口，不能宣稱完整。斷線期間資料補齊前，已保存內容可查詢但顯示不完整；舊 stream generation 事件不能污染新連線，已驗證同交易日快取不因重連消失。

一般台股全部頁籤含當日開盤與收盤撮合，排除試撮、零股及盤後定價；延後收盤依實際來源時間呈現，不挪動逐筆成交時間。來源無法證實成交性質時保留待核實狀態。完整日指截至目前已核實時點，不預先聲稱未來時段完整。

### 3. 條件、預設值與暖機

預設 A：單筆金額 ≥ 1,000,000 元；B：單筆張數 ≥ 10 張；C：單筆金額 ≥ 前 120 筆合格成交金額 P80。前置樣本不足 30 筆時 C 暫不參與；以 A AND B 或 A OR B 判定。滿 30 筆後使用目前已有的至多 120 筆，所有合格成交均更新樣本，不只大單；當前成交先判定再加入樣本。

整組 operator 只有 AND／OR，預設 AND，不提供混合分組。暖機、取樣數與百分位數也可設定；樣本數及暖機為正整數且暖機不得大於樣本數，百分位數為 1–100，金額與張數須為有效正數，數值上限於負載量測後明確鎖定。金額採可重播的十進位精度規則，避免浮點誤差跨門檻。

大單資格保持台灣 STK 整股、有效正價格／正成交量、非試撮，且時間嚴格晚於 09:00:00、早於 13:25:00。資格過濾不受 AND／OR 放寬，也不縮短全部頁籤的時間範圍。

### 4. 修改設定後重新分類

設定採共用的版本化偏好，預設所有台股面板使用同一組設定，保存後於同來源主視窗與獨立視窗同步；提供恢復預設。非法輸入顯示欄位錯誤，保留舊有效設定。重新開啟不重設有效設定。

按「套用」後從當日第一筆依時間順序重播，以每筆之前的樣本計算門檻，不能拿最新 P80 套整日。每組結果綁定 config revision＋data revision，計算中保留已標示版本的舊結果，完成才原子切換；重播期間新成交接續納入，新設定再次套用則拒收舊結果。相同設定下後續樣本變動不回寫先前分類；使用者主動更改設定才建立新的整日分類版本。

### 5. UI 與可觀測性

頁籤顯示全部 N／大單 N，並顯示已載入範圍、補齊狀態、設定摘要、暖機／重新計算狀態。最新列在上，往回查閱時新資料不得把捲動位置拉走，提供回到最新。設定元件具 label、鍵盤操作與錯誤提示；保留現有成交欄位及微秒時間格式。

## Risks / Trade-offs

- [來源可能截斷、空白或缺成交類型欄位] → 先完成唯讀來源檢查；空回應不直接等於當日零成交，缺證據時保持不完整。
- [大量逐筆資料與整日重播拖慢 UI] → 分批存取、虛擬列表、worker 或可取消的分段運算；保存 10 萬／50 萬筆負載結果與資源預算，測試不冒充真實行情。
- [跨頁競爭或關閉 owner 導致資料斷流] → lease／世代管理、接手補齊、跨視窗回歸；不得靠新增重複行情連線解決。
- [暖機期 OR 較容易符合大單] → C 未生效時顯示暖機及有效條件，數值符合使用者整組選擇。

## Migration Plan

先完成來源能力與事件身分檢查，再建立資料儲存、分類器、設定及 UI。舊 120／500 筆快取不可升格為完整日；舊固定條件不冒充使用者自訂設定，新功能初次使用採本次新預設。測試含時間邊界、重算、資料缺口、超過舊筆數、跨頁及重載。必要時可回復舊面板，但需標明近期成交限制，不刪除新格式資料。

## Open Questions

使用者操作語意已定案。待實作前驗證的是 provider 的完整交易日涵蓋、唯一事件身分、歷史／即時欄位相容性及查詢預算；這些是資料可信度 Gate，不能用假定取代。設定採全域共用是本提案的設計選擇。

## 實作量測後的資源決策（2026-09-11）

以 500,000 筆為每商品／日期的明確工作集預算；React state 僅存更新序號與可見位置，完整資料與分類索引由 session model 管理。IndexedDB 每 2,000 筆一塊，metadata 與分塊同交易提交，每 10 秒及卸載時保存；保留當日並清理超過 7 日的其他日期快取。50 萬筆實測 JS heap 約 337 MB，完整載入約 8.2 秒、33 列 DOM；超額不得靜默截斷。詳細查詢、儲存、設定上限與未完成來源 Gate 見 verification.md。

## 介面調整（2026-09-11 使用者截圖回饋）

成交明細工具列加入 i 資訊按鈕；資料狀態、已載入範圍、大單條件、排除時段、暖機及重算訊息改為點擊後在資訊對話框顯示，不占成交列表空間。資料完整性判定不變。大單金額輸入以萬元呈現，預設 100；套用時換算回元保存，既有元單位設定不遷移、不改金額。資訊與設定對話框支援 Escape 及關閉後還原焦點。
