## Context

2026-10-05 切換 1 分 K 的錯誤包含相同的 `time`／`prev time`。目前 `aggregate(candles, 1)` 直接回傳輸入，`rawRef`、`barsRef` 及尾端 Candle 因而共用物件。即時更新先更新 raw，再更新 display：跨分鐘會推入兩根相同時間的 K 棒；同分鐘也可能重複累加 volume／turnover。污染資料可被記憶體快取保存，之後同步 `setData` 再觸發整頁啟動失敗。

以上已由實際程式唯讀檢查與隔離測試重現；尚無原始 REST 證據證明來源本身重複，不將原因歸咎於供應商。圖表時間採既有 wall-clock 編碼，不能再套一次台灣時區偏移。

今日正式監控擷取仍在背景執行。此 change 不修改其程序、session、Gate 或全日驗收契約。

## Goals / Non-Goals

**Goals:**

- 原始資料與顯示資料在陣列及 Candle 層級均互不別名，合法事件只更新一次。
- 圖表提交與快取使用嚴格遞增且唯一的時間軸，正常 OHLCV／成交值不被修訂。
- 污染快取與提交例外可局部復原、可診斷，不造成整頁崩潰。
- 保護跨週期切換、歷史載入、即時尾棒與既有 viewport／指標行為。

**Non-Goals:**

- 修改來源行情、成交量單位、成交值公式、共用 SSE 或 broker 訂閱。
- 修改盤中監控排程、完整日覆蓋標準或歷史失敗證據。
- 新建服務、login、資料下載器或無限自動重試。

## Decisions

### 1. 所有聚合分支均產生獨立顯示 Candle

1 分分支同樣複製陣列及每根 Candle；raw 與 display 各自維護同一合法增量，但不共用可變物件。保留 `CommonLotVolumeCursor` 及成交值 cursor 的接受條件與 bootstrap 基準。

只複製陣列仍會使尾棒物件共用，無法避免同分鐘雙算；只在 `setData` 去重也無法修復之前已雙算的數值，因此均不採用。

### 2. 快取與提交共用時間軸完整性檢查

檢查有限且有效的時間、嚴格遞增及唯一性。正常資料逐值保留，不補假 K 棒、不猜測合併相同時間的 OHLCV，也不相加 snapshot 成交量。污染的 cache entry 視為該 key 的 miss，僅使用既有正常 bootstrap 路徑重建；不清空其他商品快取、不修改持久來源資料與證據。`remember` 拒絕保存污染資料。

即使兩根快照完全相同，也採拒絕污染快取而非修補數值的單一規則，避免將內部別名問題掩飾為成功。來源首次載入不合法時顯示局部失敗，不為此建立重複下載迴圈。

### 3. 圖表局部失敗與有界復原

提交前先驗證；`setData` 例外仍須捕捉並留下 chart key、週期及時間衝突原因，不含機密。保留同一商品／週期／generation 的最後有效系列；沒有有效系列則顯示局部錯誤狀態，不以空白冒充 ready。不得把上一商品資料當作新商品資料。一次載入最多執行一次 cache-miss bootstrap，失敗後等待明確使用者重試或正常後續載入。

### 4. 維持既有切換與歷史載入的隔離

保留 loadKey／generation guard。歷史 prepend、`reattachLiveCandleTail` 及 cache recall 都必須通過同一時間軸檢查，保留合法即時尾棒與 viewport；拖曳不改 K 棒間距、不新增假棒。日 K 與其他分鐘聚合的價量來源及 CDP／三關價／Pivot Point 計算時點不變。

## Risks / Trade-offs

- [額外 Candle 複製成本] → 維持既有載入範圍與 LRU 上限，回歸確認無持續增長；不新增每 Tick 的全市場複製。
- [拒絕污染快取可能需要重新載入] → 僅針對目前 key，沿用既有 bootstrap，不新增背景下載器或重試迴圈。
- [防呆掩蓋真實來源錯誤] → 保留原因與未通過狀態；不得將衝突數值默默合併。
- [純離線測試漏掉實際切換時序] → 真正 Chromium 重現後，優先做今日短時間 live 確認；時間或真實事件不足才延至次一適用交易日。
- [前端 HMR 可能重建圖表及影響頁面連線] → 盤中實作前保存背景擷取、session／generation、服務程序及共用連線錨點，限制變更於前端 Candle 路徑；修改後立即核對擷取仍推進。不可假設 HMR 完全無副作用；若發現需重啟共用服務或擴大訂閱才能繼續，停止該擴大操作並取得授權，不擅自處置正式擷取。

## Migration Plan

1. 待會兒實作前唯讀保存目前背景擷取程序、session／generation、資料推進、共用服務與連線錨點；不用等收盤或 cleanup，也不變更正式擷取程序或原失敗紀錄。
2. 在前端 Candle／快取範圍實作獨立所有權、完整性驗證及局部復原，先跑相應 focused tests，再執行 Chromium 重現、型別與 build；修改後立即核對背景擷取與共用服務未被中斷。
3. 優先使用既有頁面及 HMR；如需手動重載頁面或額外訂閱，依當次授權操作，不將實作授權擴張為共用服務重啟授權。
4. 今日仍有真實成交且離線回歸已通過時，立即用既有 simulation 連線及已訂閱商品跨至少三個分鐘邊界確認；保留 console、時間軸、價量增量與連線前後證據。若盤中時間／真實事件不足，明列未完成並延至次一適用交易日，不以盤後資料冒充 live。
5. 未完成 live 確認前保留未完成任務；回退僅針對本 change 的候選程式，不回退其他已修正圖表／監控程式。
