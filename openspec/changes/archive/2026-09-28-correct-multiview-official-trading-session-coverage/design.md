## Context

`stableTaiwanDailyCoverageEnd` 只用星期與 15:00 切日，健康檢查、日 K 完整度與連續性排程共用它。休市週一會被視為缺一日。既有逐商品官方月資料稽核可確認 K 棒缺口，但不能取代全市場交易日權威。

## Goals / Non-Goals

**Goals:** 以 TWSE／TPEx 官方年度日曆解析已完成交易日；來源失敗時不推定平日開市；健康、資料與排程一致；逐商品區分已覆蓋、真缺口與尚無證據。

**Non-Goals:** 不重建行情、回填 K 棒、改動個人清單或歷史失敗收據；不假定所有欠缺都是休市誤報。

## Decisions

1. 在 Worker 使用可攜、嚴格的官方日曆解析器，接受 TWSE JSON 與 TPEx 年度表；兩市場每日開休市不一致或 schema 無法辨認，整份判定視為未知。沿用既有官方來源與 bounded fetch；不將 Node 專用 `crypto`／`util` 模組打包進 Worker。本機 Worker 對外來源失敗時，由既有 Node 盤後工作取得兩份官方原始回應，經雙重驗證後透過受保護內部入口寫入有期限的 D1 日曆快取；來源過期仍維持未知。比較過「只補 9/28 特例」與「拿一檔個股月報當全市場交易日」，前者需持續手改，後者可能受停牌影響，均不採用。
2. 公用 resolver 依台北時間決定「截至上個已完成交易日」，交易日上午／盤中不提前要求當日資料，收盤 15:00 後才納入當日。對外保留判定狀態與安全 reason code；官方失敗時健康呈現 unknown，排程不啟動新的錯誤 run。
3. 逐檔重算唯讀使用目前 D1 的 `coverage_end`、`continuity_status`、`continuity_through`、缺口數與官方交易日；只有逐檔官方月資料稽核證明的日期才列「真缺口」。舊失敗與 partial 證據不改寫。

## Risks / Trade-offs

- 官方年度來源遭阻擋或短暫不可用 → 有界逾時與快取，過期且無法更新時 fail closed 為 unknown；不假裝健康。
- Worker 額外向兩官方站取日曆 → 共用 single-flight 與有效期，限制請求數；不可對每檔重複抓年度表。
- 既有 D1 continuity 元資料可能過期 → 對每檔分開呈現舊稽核與新預期日期，不把較舊的 complete 視為最新日完整。
- 本機 5174 程序未重載新程式 → 源碼與測試驗證和實際服務驗證分開記錄，不擅自重啟服務。
- 官方年曆確認的是「市場交易日」，不是每檔商品都有成交 → 不以全市場開市反推個股真缺口，完整歷史仍依官方個股月報；臨時休市若未及反映於官方年曆，須維持未知並另查官方公告。

## Migration Plan

無 schema migration。先加回歸測試及 resolver，再切換共用判定，執行唯讀逐檔稽核。若官方來源無法驗證，保留未知狀態及原資料；可回退此程式變更而不需改 D1。

## Open Questions

線上 Worker 當次能否直接取得 TPEx JSON，須以安全的非機密 response schema 與測試確認；若不能，應持續回報 unknown，另立資料來源改善工作。

## 交易日定義

本 change 的「交易日」指 TWSE 與 TPEx 官方年度開休市資料均判定市場開市的日期，並不要求每檔商品當天有成交。個股是否缺 K 棒由官方個股歷史資料另外判定。若遇臨時停市而官方年度表尚未更新，不能從某檔沒有 K 棒倒推全市場休市；需另查兩市場官方臨時公告，此情境維持待查，不改寫既有資料。
