## Context

使用者已確認第一版採收盤後選股，範圍為全部上市與上櫃普通股；兩項條件為前一交易日成交量的 3 倍以上，以及千張大戶持股比例週增至少 0.2 個百分點。其餘互動沿用前一輪草案：條件可獨立使用、組合預設全部符合、結果點選連動 K 線圖。

本次提案位於 RealTimeStock 根專案。`src/lib/workspace.ts` 的 `BlockType`／`BLOCK_META` 管理可加入與保存的面板；`src/App.tsx` 的 `useBlockContract` 以 pin 或全域 selected 決定商品。現有 `selectByCode` 能選取不在自選清單中的商品，但同時影響其他未鎖定面板，因此不能直接當成圖表專用選股事件。

`src/components/scanner-panel.tsx` 目前以三種前 100 名排行合併，再截取最多 30 筆複選結果，不是全市場篩選。`src/lib/stock-index.ts` 的券商商品目錄可協助最後的合約解析，但不能以券商當下可讀商品或持有清單代替完整官方母體。

本機 MultiView 已有官方商品目錄、TDCC 17 級完整性檢查、盤後 pipeline 與 repo 外本機 D1。現有 TDCC 收集會依 active targets 篩選；官方名冊被觀察到，不代表每檔已保存連續兩週。因此必須先做唯讀覆蓋盤點，不把既有回補成功視為全市場已可選股。

## Goals / Non-Goals

**目標：**

- 在本機主介面提供可移動、縮放、保存的獨立選股面板。
- 從完整普通股母體計算，對每檔回傳可追溯條件判定與日期，漏資料不漏列帳。
- 重用合法盤後資料基礎，以每日批次量與每週整批 TDCC 資料建立選股底稿，不新增全市場即時訂閱。
- 圖表專用連動、安全缺值、可恢復資料更新及相容的工作區保存。

**非目標：**

- 盤中選股、成交量預估、歷史任意日期回測、買賣建議、自動加入清單或任何委託操作。
- ETF、ETN、權證、特別股、興櫃、海外股票，以及已放棄的券商分點主力功能。
- Sites／Cloudflare 部署、遠端 D1 寫入、MultiView 新介面或桌面封裝版的新增整合。
- 為全市場每檔啟動一年歷史回補，或改變既有大戶／散戶副圖的儲存與顯示契約。

## Decisions

### 1. 獨立選股面板與條件模型

新增 `screener` 面板，第一版每個工作區最多一個；不改既有預設版面、不強制開啟。兩個穩定條件 ID 為 `volume-multiple` 與 `large-holder-weekly-pp`，預設兩項勾選，門檻分別為 `3` 與 `0.2`，組合為 `all`；可改 `any`。門檻使用有限範圍十進位輸入：成交量倍數 `0.01–1000`、最多兩位小數；持股比例週增 `0.01–100` 個百分點、最多兩位小數。無條件、空白、負數、非數值或超界不送出查詢，不以預設值悄悄替換。

條件與結果使用面板內部捲動，避免短 viewport 或特大字級讓固定條件區占滿可用高度；不增加頁面橫向捲動。欄位為代碼／名稱／市場、成交量倍數、前日與當日量、大戶前週與本週比例、週增百分點；窄面板以換行卡片保留比較原值，來源與缺漏說明可展開。條件變更後明示「尚未套用」，按「開始篩選」才替換結果。

相較修改排行榜，獨立面板避免把 Top-N 即時行情與完整盤後篩選混用；相較複製自選清單 CRUD，只重用樣式及可存取清單互動，不保存結果成個人清單。

### 2. 全市場母體與日期錨點

用官方名冊的市場、商品種類、上市櫃狀態與生效日期建立 `universeRevision`；不能只靠代碼長度、尾碼、排行或清單推定普通股。母體包含暫停交易但尚未下市櫃的普通股；新上市無比較期、停牌無量等狀態在母體中保留 reason。商品移轉市場以有效日期與穩定識別映射，不能將 `.TW`／`.TWO` 重複計入。

每次快照固定 `D`（本次日資料交易日）、`P`（D 的前一個適用官方交易日）、`W`（最新已公布週資料日）、`Wprev`（前一官方週期）、`generatedAt`、`expectedSessionDate` 及來源發布／擷取資訊。首版不提供任意 as-of 歷史查詢。

每日底稿以兩市場可用的共同已公布交易日為錨點；一邊尚未公布時不混接不同 D。若官方日曆／臨時休市使共同錨點不可證明，保持原已驗證快照並顯示等待／無法判定，不猜平日。最新週期按官方期別排序，不硬減七天。整體新一期尚未公布時可保留上一個明確標日期的已驗證快照；同一目標期個別商品缺列時不能逐檔退回更舊日期。

### 3. 精確條件計算與資料缺口

成交量判定為 `V(D) >= multiplier × V(P)`，且 `V(P) > 0`。使用經確認同交易範圍的官方日總成交量，保留來源欄位／單位／正規化版本；內部以精確股數與十進位門檻交叉相乘，不用顯示後的四捨五入值判定。主圖 Shioaji Kbars 的 canonical 張數契約保持不變，不用 `Snapshot.volume_ratio` 或成交量均量比替代本公式。

TDCC 先驗證 1–15 級、調整項與合計的完整性及對帳，再使用第 15 級官方 `ratioPercent`，定義為「占集保庫存數比例」。`deltaPp = ratioPercent(W) - ratioPercent(Wprev)`；60.00 → 60.20 是 +0.20 個百分點，60.00 → 60.12 不是。以官方小數精度計算，避免浮點邊界；不把集保庫存比例改稱已發行股數比例。

每個啟用條件輸出 `pass | fail | unknown` 與有限 reason code。未知原因包括 `missing_current_session`、`missing_previous_session`、`zero_previous_volume`、`missing_current_week`、`missing_previous_week`、`invalid_distribution`、`incomparable_source`、`instrument_mapping_unknown`。不得補零、forward-fill、找最近兩筆跳期比較或以未驗證來源硬補；合法當日零量且前日量正值則量增條件為 fail。

三態組合使用以下規則，避免把缺值一律當不符合：

| 組合 | 有足以確定的結果 | 其他狀況 |
| --- | --- | --- |
| `all` | 任一 fail → fail；全部 pass → pass | unknown |
| `any` | 任一 pass → pass；全部 fail → fail | unknown |

只評估啟用條件。`matched + notMatched + unknown = total`，`evaluated = matched + notMatched`，每檔都必須被處理；另列各條件 `missingCount`，即使 OR 已確定符合，另一條件缺資料仍顯示。UI 的「無法判定」對應組合 unknown，而非把可重疊的欄位缺漏數加入互斥總數。

### 4. 全市場底稿獨立保存，重用本機資料服務

使用 `apps/multiview` 的本機 Worker／D1，增加獨立選股資料表與 source adapter，避免新增第二套行情服務。規劃的邏輯資料為：

- `screener_universe`：名冊版本、商品識別、市場、種類及生效區間。
- `screener_daily_volume`：商品、交易日、精確量、來源單位與交易範圍、修訂與驗證狀態。
- `screener_tdcc_weekly`：商品、官方週期、第 15 級比例、完整性摘要、source revision；可重用已驗證完整 TDCC 列作來源，不得只驗單級。
- `screener_runs`／`screener_snapshots`：scope、checkpoint、名冊與來源版本、期間、逐條件覆蓋、immutable snapshot ID 與啟用指標值。

市場資料底稿與個人清單、既有 `tdcc_continuous_symbols` 及一年歷史工作佇列隔離。最新 TDCC 整批 payload 由全市場母體過濾保存，不把母體整批改為現有 active targets。每檔異常只污染自己的狀態，不能因一筆無效列讓所有有效商品失效；整批來源日期錯誤則拒絕整批發布。

以下官方來源已完成 task 1 的欄位、涵蓋與使用規範驗證；可重現入口、資料日期及 hash 見 `verification.md`：

| 用途 | 官方入口 | 實作前確認 |
| --- | --- | --- |
| 上市名冊與日量 | https://openapi.twse.com.tw/ | 普通股分類、完整名冊、`STOCK_DAY_ALL` 日量欄位、交易範圍與前期取得方式 |
| 上櫃名冊與日量 | https://www.tpex.org.tw/openapi/ | 普通股分類、收盤行情欄位及單位，不能混用排行或不同成交範圍 |
| TDCC 最新整批週資料 | https://openapi.tdcc.com.tw/ 、https://data.gov.tw/dataset/11452 | 第 15 級、完整性、來源日期、授權與顯名要求 |
| TDCC 週期說明與歷史入口 | https://www.tdcc.com.tw/portal/zh/smWeb/qryStock | 官方週期、允許取得的歷史途徑；不得假設 latest API 可要求任意歷史日 |

實作採公司基本資料的普通股種類／有效日期，加上 TDR 排除資料建立母體；不僅看四碼代號。TWSE／TPEx 每日報表的「成交股數」已與正式 OpenAPI 同日逐檔對帳。TDCC 最新資料採官方整批資料；必要前週採使用者授權的本機原生公開表單、有界低速查詢。403／CAPTCHA 一律停止，不能因免費頁面可讀就擴大自動歷史介接範圍。

### 5. 更新與首跑策略

全市場資料準備接到既有本機盤後維護架構的獨立 `screener-daily`／`screener-weekly` scope，市場收盤僅代表可檢查，必須來源實際發布才處理。UI「開始篩選」只讀底稿並計算，不觸發逐商品 Kbars、TDCC 歷史查詢或全市場訂閱。

實際入口為 `scripts/stock-screener-update.mjs`。既有每日工作在 16:45 執行，不能等同來源已完整發布；新增 scope 只在台北時間 18:00 後檢查，並接到既有每五分鐘 TDCC watcher 的原工作完成／佇列空閒分支。成功後一小時冷卻，daily／weekly 來源分別六／二十四小時去重；休眠恢復後由既有 watcher 下一次執行補檢查，不新增或重啟 LaunchAgent。排程預設關閉，兩期快照及來源證據通過後才開啟；排程不帶 `--bootstrap-week`。

每 scope 採單一 lease、每來源 single-flight、有界批次、checkpoint、最多 2 個外部請求併發；完整 fetch＋body 解析上限 30 秒，單次執行上限 15 分鐘，每個失敗工作最多 3 次自動重試並遵守較嚴的官方限制／Retry-After。失敗後保留已驗證底稿與安全原因，下次窗口或恢復執行可續作，不能 busy-loop。既有行情、TDCC／PE 工作保持優先與可用。

首跑先唯讀核對本機名冊、兩個日交易日及相鄰兩週的逐商品覆蓋，只補所需期間。優先合法且可驗證的本機資料；其次用經核准官方批次歷史／匯入。若 latest-only 來源缺前期且無合法補法，明示 bootstrap pending，等待下一期正常累積，不能以當週副本、手動假值或繞過 CAPTCHA 填滿。未取得可比較來源前不得宣稱完整上線。

### 6. 版本化唯讀查詢與失敗隔離

已實作 `GET /api/stock-screener/status` 與 `GET /api/stock-screener/results`；主介面經精準同源路由連到 5174 的本機限定處理器。路由在一般 `/api` 券商 proxy 前處理；只允許固定 loopback 目標、GET、有限 query schema，不接受使用者傳入 upstream URL、SQL 或任意 path。不得藉新路由轉送交易／帳務／runtime 管理或對外網站；hosted target 不啟用本機選股路由。

results 請求包含啟用條件、門檻、`all | any`、有限排序與每頁最多 100 筆的 cursor。回應包含 schema／formula version、`snapshotId`、`universeRevision`、`criteriaFingerprint`、資料日／週、總數與逐條件覆蓋、匹配列及安全原因。另以有限的 `resultState=unknown` 檢視無法判定的商品；排序與分頁只裁切完整判定集合。disabled 條件的缺口不得阻斷單條件查詢。

日量與週資料各自維護 readiness；未啟用且未取得的資料族群，其日期／指標可為 null 並顯示未提供，不作為快照發布或查詢成功的前置條件。只有週條件時不要求日量底稿就緒，只有日量條件時亦不要求 TDCC 就緒。狀態按本次啟用條件彙整，底層其他資料族群的健康資訊另外呈現。

分頁綁定同一快照與條件，快照更新不能導致漏列／重複；不存在或已淘汰快照回明確 `snapshot_expired`，請使用者重新篩選。非首頁禁止默默選用新快照。初始保留最新兩個完整發布快照，頁面不得長期宣稱過期結果為最新。

快照 staging 成功且所有商品都有判定紀錄後原子發布；同日期正式修訂可產生新版本。同一期較新但稀疏／無效回應不得覆寫較完整且已驗證資料；進入新的官方期別時，合法缺值以 unknown 發布並保留前版，不能因舊期較完整而永遠卡住日期。正式來源 receipt 與新期別證據必須通過，禁止逐檔猜期。正式名冊每市場最低 800／500 檔，與上一發布版相比縮水超過 5% 亦拒絕發布。回應區分 `ready`、`partial`、`pending`、`stale`、`unavailable`；處理完母體不等於每個條件都有資料。

服務離線時顯示最後結果的真實日期與離線標籤，禁止換條件後重標舊結果；HTTP 200、非零 row count 或單一 symbol 成功不能當成全市場就緒。

### 7. 圖表專用連動與保存相容

若只有一張未鎖定 K 線圖，自動選它為連動目標；有多張則提供目標選擇器並保留合法選擇。沒有圖表時提供明確「開啟 K 線圖」動作，使用者啟用才新增日 K 圖；全部鎖定時提示先解鎖或明確新增，不擅自解除 pin。

使用 typed chart-target 選擇事件，只包含已驗證的市場／商品識別、目標 block ID 與 generation；不得把選股歷史列偽裝成最新 quote snapshot。目標以既有合法 contract resolver 及行情讀取路徑載入 K 線；沒有合約或即時服務時顯示圖表載入失敗，但不丟掉篩選結果。

圖表專用商品覆寫狀態在 session 中管理，只有 chart block 採用；較新的全域自選選擇清除未鎖定圖表的暫時覆寫，恢復既有跟隨語意。明確鎖定時必須鎖目前真正顯示的商品。目標移除、切換、鎖定或連點另一列時，舊 generation 回應不得覆蓋新目標；其他圖表、下單、智慧下單與自選清單不變。

選股偏好以新版本化的同 origin key 保存，不變更既有 workspace／profile key 或破壞 schema；僅保存條件、排序及可驗證的目標參照，不把條件寫進舊 Block 必填欄位。舊版面可以沒有 screener，新加入面板由既有 Block registry 納入版面保存；失效目標在載入後安全重選。結果只在記憶體保留，重整後重新讀取合法快照，不把 localStorage 當正式市場資料庫。

## Risks / Trade-offs

- [名冊分類不足或市場轉換] → 先完成官方分類與有效日期 mapping；未辨識紀錄顯示母體不完整並阻止完整宣告，不用數字字首猜商品類型。
- [前一日／前一週資料不齊] → 明示 unknown 與 bootstrap pending，只補必要期間；無合法歷史來源就等待自然累積並保留未完成任務。
- [日資料與週資料頻率不同] → 各列／面板保留兩種日期與發布資訊，不暗示持股每日更新或支援回測。
- [兩市場日量交易範圍或單位不同] → 逐市場固定且版本化欄位契約，兩期同口徑；不把官方股數與 Shioaji 張數直接比值。
- [比率邊界與股權結構變動] → 用官方精度與完整級距資料計算；股數／資本變動可能影響比例，UI 不將比例變化解讀為可證明的買進行為。
- [新底稿增加本機 D1 成本] → 分開存選股需要的日量與週摘要、限制快照保留，不啟動全市場長歷史任務。
- [5174 暫停使選股查詢不可用] → 接受既有本機資料服務依賴，面板清楚報錯，不自動啟停服務、不把券商可登入當成替代健康訊號。
- [圖表專用選擇與全域 pin 互動] → 以單一目標事件與 generation 處理，實測鎖定、全域選擇、連點與下單面板不變。

## Migration Plan

1. 完成 task 1 的來源、名冊、期間、授權與本機只讀覆蓋證據，未通過者先標阻礙。
2. 建立純計算與 fixtures，再以 staging DB 套用 additive 選股 tables；備份、schema 與 integrity 通過後才依既有流程遷入 live 本機 D1。
3. 實作本機限定查詢、完整性統計及 background scope，先驗證日量與週資料各自可用；只讀 API 不攜帶維護 credential。
4. 接入選股 UI、圖表專用連動與工作區相容行為，完成有界真實資料更新與 UI 驗收。
5. 回退只停用新選股入口／新 scope，保留 additive tables、舊快照及備份；不得停 simulation API、watchdog、5173、5174、既有 pipeline 或行情連線。
6. 全部實作與實際驗收通過後才另行討論正式 specs 同步與歸檔；commit、push、部署及服務重載不是本提案建立的授權。
