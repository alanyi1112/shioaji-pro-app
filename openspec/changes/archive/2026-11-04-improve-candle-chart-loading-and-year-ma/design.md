## Context

本文件回補 11/03–11/04 已完成的圖表改善，實作、歷史失敗與實際頁面證據分列於 verification。原始分鐘資料、盤中監控與盤後基準必須保持原有權威。

## Goals / Non-Goals

**Goals:** 本機 K 線能送達原 API；新增可驗真的展示專用日線前綴讓 SMA240 正常暖機；移除指定三行資訊，保留原圖表操作。

**Non-Goals:** 改寫分鐘基準、放寬來源或預算 Gate、保證新上市商品有 240 根，或證明供應商全期間資料無缺口。

## Decisions

- **本機傳輸分流沿既有契約。** kbar-request-base 只對 HTTP Vite／空 API base／loopback 使用同 port 的另一個本機 hostname，減少與 SSE 的瀏覽器連線競爭；明確 API base、Tauri 與打包版不套用。保留期限及失敗通知，不用隱藏黃框掩飾逾時。
- **日線前綴與分鐘權威分開。** 固定本機 5174 的 1d 路徑最多 500 筆，核 schema、商品、canonical common_lot、台北 09:00 標準日棒及時間軸。與近期資料至少三個已結束重疊樣本、全部重疊 close 互證後才 prepend。直接下載更多券商分鐘 K 會增加共用資源壓力，因此不作為暖機備援。
- **年線沿既有參考均線組。** 增加 ma240 output、樣式與圖上讀值，既有保存設定透過既有正規化補齊；不足期數維持 whitespace。
- **隱藏資訊不刪計算。** 左上角 reference 與兩種比較基準列不渲染，壓撐／費波線與百分比仍依原分母，診斷屬性保持；固定 reference 的回到最新在壓撐選單。
- **增量日線保持視窗。** 被動 prepend 依新增筆數平移原 logical range，不重設縮放、價格軸或即時尾端。

## Risks / Trade-offs

- [日線來源不可用或價格基準不符] → 拒絕合併並維持近期資料，不改抓券商分鐘歷史。
- [商品上市未滿一年] → 保留真實長度，年線暫無值。
- [暖機資源競爭] → 同商品合併、單序上游、最多八項等待、24 項快取、成功 30 分鐘與失敗 1 分鐘冷卻、有界回應及期限。
- [既有全專案檢查失敗] → 列為基線缺口，僅以本案 focused 結果及實際畫面結案。

## Migration Plan

程式先前已載入，本輪不重新安裝或觸發頁面更新。同步兩份既有正式條款及新增日線展示規格後歸檔；如需回復程式必須另核共享檔案範圍，不直接覆蓋混合工作桌。

## Open Questions

本案結案無未決實作項目；全期間資料完整性及四個監控／恢復大案不在本案完成宣告範圍。
