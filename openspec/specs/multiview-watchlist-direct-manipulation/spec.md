# MultiView 自選清單直接操作規格

## Purpose
定義 MultiView 線圖商品的跨頁籤移動、複製與快捷移除行為，確保操作具備明確成員身分、等價的非拖曳入口、可辨識回饋，以及限定使用者與頁籤的原子寫入。

## Requirements

### Requirement: 線圖商品可以拖到其他頁籤並明確區分移動與複製
MultiView MUST 允許使用者將目前頁籤實際收錄的線圖商品拖到另一個啟用中的頁籤標題。Mac 上不按 Option 放開時 MUST 移動商品；放開時按住 Option MUST 複製商品。成功後目的頁籤 MUST 恰有該商品一筆，且該商品 MUST 位於第一位；複製 MUST 保留來源，移動 MUST 只移除指定來源頁籤的成員資格。頁籤內拖放 MUST 維持既有排序行為。

#### Scenario: 拖到不同頁籤並移動
- **WHEN** 使用者將來源頁籤已收錄的商品拖到另一個啟用頁籤標題，且放開時未按 Option
- **THEN** 目的頁籤的商品位於第一位，來源頁籤不再收錄該商品，其他頁籤的相同商品保持不變

#### Scenario: 放開時按住 Option 並複製
- **WHEN** 使用者將來源頁籤已收錄的商品拖到另一個啟用頁籤標題，且放開時按住 Option
- **THEN** 目的頁籤的商品位於第一位，來源頁籤仍收錄該商品，介面明確回報「已複製」

#### Scenario: 頁籤內拖曳與無效落點
- **WHEN** 使用者在原頁籤內放開，或在頁籤及合法排序區域之外放開
- **THEN** 原頁籤內放開 MUST 只依既有規則排序；無效落點 MUST 取消操作，且不得修改任何頁籤

#### Scenario: 拖曳中改變 Option 或取消
- **WHEN** 使用者在拖曳途中按下或放開 Option，或按 Escape、失去視窗焦點、觸發 pointercancel
- **THEN** 提示 MUST 反映放開時的移動／複製模式；取消時 MUST 清除預覽與指標且不得寫入清單

### Requirement: 跨頁籤操作必須使用確切成員身分且避免重複
跨頁籤操作 MUST 以使用者身分、來源頁籤 identity、目的頁籤 identity 及商品代號辨識成員，不得只依頁籤名稱或目前線圖顯示代號寫入。系統頁籤與個人頁籤 MUST 都可作為來源及目的地；目的地已有該商品時 MUST 保留目的地既有資料並將其移到第一位，不得新增重複列或覆寫目的地備註。

#### Scenario: 目的頁籤已有相同商品
- **WHEN** 商品已存在於目的頁籤，使用者仍要求移動或複製
- **THEN** 系統 MUST 將目的地既有商品置頂且維持一筆；複製 MUST 保留來源，移動 MUST 移除來源；目的地既有備註與商品 metadata MUST 不被來源覆寫

#### Scenario: 系統頁籤之間複製
- **WHEN** 使用者將商品從一個系統頁籤複製到另一個系統頁籤
- **THEN** 兩個系統頁籤 MUST 分別保留該商品，重新載入後仍正確，且共享預設清單 MUST 不被改寫

#### Scenario: 暫時顯示其他商品或過期頁籤
- **WHEN** 線圖目前顯示的商品與卡片所屬清單商品不一致、來源成員已消失，或來源／目的頁籤身分已變更
- **THEN** 系統 MUST 拒絕跨頁籤操作並顯示可理解的原因，不得把未確認的顯示代號當成清單成員

#### Scenario: 目的頁籤停用或與來源相同
- **WHEN** 目的頁籤已停用、不存在或與來源相同
- **THEN** 系統 MUST 不執行跨頁籤 mutation；同頁籤只能使用既有排序操作

### Requirement: 線圖可直接從目前頁籤移除商品
MultiView MUST 在線圖右鍵功能表及卡片標題的可見操作入口，提供「從『頁籤名稱』移除『商品代號』…」。操作 MUST 先確認頁籤與商品身分，並在使用者確認後只移除目前頁籤成員資格，不得刪除商品 catalog、歷史 K 線、其他頁籤成員或 RealTimeStock 清單。

#### Scenario: 確認移除目前頁籤商品
- **WHEN** 使用者在符合清單成員身分的線圖上選擇移除，並於確認對話框確認
- **THEN** 系統 MUST 只從明示的頁籤移除該商品，並顯示成功回饋；目前頁籤保持不變，線圖位置由下一個商品遞補，若原本是最後一個則用上一個，清單為空則顯示空狀態

#### Scenario: 取消移除
- **WHEN** 使用者取消或關閉確認對話框
- **THEN** 商品、排序與目前線圖 MUST 保持不變

#### Scenario: 顯示商品不是卡片清單商品
- **WHEN** 線圖顯示代號與卡片原屬的清單商品不同，或該卡片沒有可確認的清單成員
- **THEN** 快捷移除 MUST 不可執行，且介面 MUST 說明需先回到清單商品，不得默默刪除任一代號

#### Scenario: 移除系統預設商品
- **WHEN** 使用者確認移除系統頁籤中的預設商品
- **THEN** 系統 MUST 只為該使用者、該系統頁籤保存隱藏覆寫，不得修改共享預設或其他系統頁籤

### Requirement: 移動、複製與移除必須提供非拖曳操作及明確回饋
卡片標題的操作入口與線圖右鍵功能表 MUST 提供等價的移動、複製及移除操作。使用者 MUST 能以單指標點選及鍵盤完成跨頁籤操作；拖曳期間 MUST 顯示合法落點、目標頁籤與目前移動／複製模式，且不得僅靠顏色區分。成功、等待、衝突及失敗 MUST 有可辨識的回饋。

#### Scenario: 不使用拖曳的移動或複製
- **WHEN** 使用者透過線圖操作選單選擇「移動到」或「複製到」及目標頁籤
- **THEN** 系統 MUST 執行與拖放相同的成員及排序規則，並可由鍵盤完成

#### Scenario: 落點預覽及不切換頁籤
- **WHEN** 使用者將商品拖到合法目的頁籤上方但尚未放開
- **THEN** 頁籤 MUST 提供清楚的落點與模式預覽，且 MUST 不因 hover 自動切換目前頁籤、重建線圖或寫入清單

#### Scenario: 操作成功後維持目前視圖
- **WHEN** 移動、複製或移除成功
- **THEN** 系統 MUST 顯示明確結果，且 MUST 不自動切換作用中頁籤或讓未受影響的線圖跳到其他商品

### Requirement: 清單 mutation 必須原子化且限定使用者與頁籤
跨頁籤移動、複製與快捷移除 MUST 由伺服器驗證目前使用者、頁籤身分、來源成員與目的狀態。移動的目的地置頂與來源移除 MUST 在同一原子寫入中完成；伺服器不得信任前端提交的整份舊排序來覆寫其他並行修改。失敗或衝突 MUST 保留原清單並要求重新讀取，不得宣稱成功。

#### Scenario: 目的地寫入失敗
- **WHEN** 跨頁籤移動的任一步驟失敗
- **THEN** 來源與目的頁籤 MUST 保持寫入前的持久狀態，並顯示錯誤；不得留下只加入目的地或只移除來源的半成品

#### Scenario: 同時修改頁籤或商品
- **WHEN** 執行前來源商品已不在原頁籤、目的頁籤已變更，或排序狀態與伺服器不同
- **THEN** 系統 MUST 以衝突回應拒絕過期請求或依伺服器最新狀態安全收斂，不得套用前端過期的整份清單

#### Scenario: 未登入或不同使用者
- **WHEN** 未登入或請求嘗試操作不屬於目前使用者的成員
- **THEN** mutation MUST 失敗且不得修改任何清單資料

#### Scenario: 既有資料與交易邊界
- **WHEN** 任一跨頁籤或快捷移除操作成功或失敗
- **THEN** 變更 MUST 只作用於 MultiView 清單；Shioaji 清單、行情連線、交易、商品 catalog、歷史資料及其他使用者的清單 MUST 保持不變
